# Skills

Portable agent skills for the Zed Agent, Claude Code, and Codex. They bring a Lead / PSE / Review
engineering team, a Spec Kit and Gitea workflow, and a deterministic control plane to any repository.
Each folder here is self-contained: `SKILL.md`, stdlib-only Python scripts (3.9 or later) that print one
JSON envelope, vendored contracts, evals, and tests. Nothing here imports from `skill-lab/` at
runtime. The rules are in [CONVENTIONS](../skill-lab/docs/CONVENTIONS.md).

`CATALOG.json` is generated by `skill-lab catalog` and lists the skills that actually exist. Never edit
it by hand.

## Install

Run this from the repository root. It creates relative symlinks, so the repository works wherever it
is cloned:

```sh
python3 skill-lab/bin/skill-lab install                      # every runtime: .agents/skills/ and .claude/skills/
python3 skill-lab/bin/skill-lab install --runtime zed        # .agents/skills/<name> (Codex reads it too)
python3 skill-lab/bin/skill-lab install --runtime claude     # .claude/skills/<name>
python3 skill-lab/bin/skill-lab install --global             # ~/.agents/skills and ~/.claude/skills
python3 skill-lab/bin/skill-lab install --check              # exit 1 if any link is missing or stale
```

Use `--mode copy` for a file system or runtime that does not follow symlinks.

| Runtime | Discovery folder | Setup |
|---|---|---|
| Zed Agent | `<worktree>/.agents/skills/` (trusted worktrees only), `~/.agents/skills/` | [Zed config](../skill-lab/config/zed/README.md), [Zed + Ollama runbook](../skill-lab/docs/runbooks/zed-ollama-setup.md) |
| Claude Code | `.claude/skills/`, `~/.claude/skills/` | [Claude Code config](../skill-lab/config/claude/README.md) |
| Codex | `.agents/skills/`, from the working directory up to the repository root | [Codex config](../skill-lab/config/codex/README.md) |

## Invoke

| Runtime | Explicit | Automatic |
|---|---|---|
| Zed Agent | `/lead-architect`, or `@skill` and pick one | The agent loads a skill through the `skill` tool when your request matches its description. That prompts unless it is allowed in `tool_permissions` |
| Claude Code | `/lead-architect` at the start of a message | Claude loads it when relevant |
| Codex | `$lead-architect` | Codex picks it when relevant |

A skill's commands use paths relative to its own folder (`python3 scripts/<script>.py ...`). Each
`SKILL.md` has a `## Runtime notes` section that says how each runtime resolves that folder. Scripts
are read-only by default. Any external change needs `--apply` and is still limited by the project's
autonomy level (`.skill-policy.json`; a missing file means `shadow`).

## Add a skill

1. Scaffold it. Either ask an agent with `/skill-forge` (`$skill-forge` in Codex), or run:

   ```sh
   python3 skill-lab/bin/skill-lab new my-skill --family meta --spec SPEC-014 --author "Your Name"
   ```

   This writes `skills/my-skill/` and `skill-lab/specs/014-my-skill/` from the template, with every
   blank marked `TODO(scaffold)`. The vendored `_skillkit` and schemas are included.
2. Write the `SKILL.md` body, the scripts, the spec, and the evals: at least 4 deterministic cases,
   2 agentic cases, and 3 positive plus 1 negative trigger cases (CONVENTIONS §5).
3. Check it until it is clean:

   ```sh
   python3 skill-lab/bin/skill-lab sync --skill my-skill
   python3 skill-lab/bin/skill-lab validate --skill my-skill
   python3 skill-lab/bin/skill-lab test --skill my-skill
   python3 skill-lab/bin/skill-lab bench --skill my-skill --tier deterministic
   python3 skill-lab/bin/skill-lab catalog
   python3 skill-lab/bin/skill-lab score --skill my-skill
   ```

4. Register it. Add a row to the spec table in CONVENTIONS §6, add a row to the catalog above, and add
   the name to the skill allow rules in the runtime templates under `skill-lab/config/`. The lab test
   `test_configs.py` checks that the templates and this README name exactly the skills in that table.

A skill is done when it meets the definition of done in CONVENTIONS §9.
